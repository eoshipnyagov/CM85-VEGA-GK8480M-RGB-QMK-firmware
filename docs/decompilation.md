# Декомпиляция прошивки

Для бинарника `VEGA_vial_v1_01_20231201.bin` введён воспроизводимый первый
проход:

```text
python tools/decompile_firmware.py firmware/original/VEGA_vial_v1_01_20231201.bin
```

Он строит каталог предполагаемых функций из:

- адресов активных векторов;
- целей прямых `BL`/`BLX` переходов;
- адресной базы `0x08000000` и Thumb-режима.

Имена пока имеют два уровня достоверности:

- подтверждённые роли: `reset_startup`, `svc_rtos`, `systick_rtos`;
- рабочие гипотезы: `irq_vector_NN` и `sub_XXXXXXXX`.

Полный машинный листинг генерируется отдельно через установленный ARM
`objdump`. Он сохраняется локально в `analysis-output/full-thumb-disassembly.txt`
и не включается в Git из-за размера.

## Как будем давать имена

Имя закрепляется только после проверки нескольких признаков:

| Рабочее имя | Что должно подтвердиться |
|---|---|
| `usb_irq` | доступ к USB-регистрам, endpoint/status-поля, вызовы HID-логики |
| `vendor_hid_dispatch` | сравнения байта команды, длина 32-байтного отчёта, таблица ответов |
| `i2c2_transport` | записи/чтения I2C-регистров, START/STOP, адрес ведомого |
| `gpio_matrix_scan` | повторяющийся цикл по линиям, чтение входов и запись выходов |
| `key_debounce` | маски/счётчики стабильности и переходы состояний |
| `rgb_update` | длинные последовательности записей цветов или таймингов |
| `vial_protocol` | vendor HID dispatch и известные Vial/VIA структуры |

## Ограничение результата

Это восстановление логики, а не получение исходного проекта. Сохранятся
условия, циклы, обращения к памяти и вызовы, но не исходные имена, типы и
комментарии. Поэтому каждое имя будет сопровождаться уровнем уверенности и
xref на подтверждающие инструкции.
