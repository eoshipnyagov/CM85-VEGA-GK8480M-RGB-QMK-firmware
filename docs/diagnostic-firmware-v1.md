# Диагностическая прошивка KD85 VEGA — итерация 1

Исходный код находится в [`firmware/diagnostic/`](../firmware/diagnostic/). Это
overlay для QMK/Vial, а не готовый к прошивке образ: матрица KD85, RGB-пины,
пины дисплея и межплатный bus пока не подтверждены.

## Цель

Сначала проверяем безопасный канал `ПК → USB Raw HID → WB32 → USB Raw HID → ПК`.
Только после этого добавляем чтение неизвестных шин. Существующая клавиатура и
Vial должны сохранить штатный USB-протокол.

## Формат отчёта

Все отчёты имеют длину 32 байта — это соответствует двум vendor-HID каналам,
обнаруженным в оригинальном бинарнике.

| Смещение | Запрос | Ответ |
|---:|---|---|
| 0 | Команда | Команда |
| 1 | Sequence | Status |
| 2 | Свободно | Sequence |
| 3–31 | Payload | Payload |

Команды первой итерации:

| Код | Имя | Результат |
|---:|---|---|
| `E0` | `PING` | `OK`, sequence и uptime QMK, big-endian, 4 байта |
| `E1` | `INFO` | `OK`, версия протокола `1.0`, подпись `KD85 VEGA` |
| `E2` | `I2C_SCAN` | `NOT_IMPLEMENTED` |
| `E3` | `I2C_READ` | `NOT_IMPLEMENTED` |
| `E4` | `SPI_JEDEC` | `NOT_IMPLEMENTED` |
| `E5` | `SPI_READ` | `NOT_IMPLEMENTED` |

Статусы:

| Код | Значение |
|---:|---|
| `00` | `OK` |
| `01` | `BAD_LENGTH` |
| `02` | `UNKNOWN_COMMAND` |
| `03` | `NOT_IMPLEMENTED` |

Пример запроса:

```text
e0 07 00 00 00 00 00 00 ...
```

Ответ начинается так:

```text
e0 00 07 <uptime: 4 bytes, big-endian> ...
```

## Почему шины пока отключены

В бинарнике подтверждена конфигурация периферии `I2C2`, но не подтверждены
физические SDA/SCL, уровни, slave-адреса и владелец шины. Для SPI аналогично
не установлены точные `CS` и связь с `PY25Q128HA`/`P25D80SH`. Поэтому первая
прошивка не пишет GPIO и не обращается к I²C, SPI, TFT, RGB или внешней flash.

## План итерации 2

1. Создать отдельный target KD85 на базе найденной в QMK поддержки `WB32FQ95` и
   `wb32-dfu`, не подставляя пины от другой клавиатуры.
2. Добавить host-тестер Raw HID и проверить `PING`/`INFO` на собранном образе.
3. Подтвердить распиновку осциллографом/логическим анализатором.
4. Реализовать только read-only `I2C_SCAN`, затем RTC read.
5. Реализовать `SPI_JEDEC` и ограниченное чтение flash; команды записи оставить
   выключенными.

До завершения пункта 1 этот код не следует превращать в `.bin` для загрузки в
клавиатуру: overlay сам по себе не содержит корректной KD85 матрицы и может
собраться только как часть полноценного QMK target.
